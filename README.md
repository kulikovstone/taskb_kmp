Проект Kotlin Multiplatform для Android, iOS, Web, настольных приложений (JVM) и сервера.

Основная разработка сейчас ведётся для Desktop; следующая платформа — Android.
Модули и целевые платформы iOS и Web сохранены как каркас на будущее.

* [/app/iosApp](./app/iosApp/iosApp) содержит приложение для iOS. Даже при использовании общего
  интерфейса на Compose Multiplatform для iOS нужна отдельная точка входа.
  Здесь также следует размещать код SwiftUI.

* [/app/shared](./app/shared/src) содержит общий код приложений на Compose Multiplatform.
  Внутри расположены следующие каталоги:
    - [commonMain](./app/shared/src/commonMain/kotlin) — код, общий для всех платформ.
    - Остальные каталоги содержат точки входа для конкретных платформ: Android, Desktop,
      iOS и Web.

* [/core](./core) содержит модули общей инфраструктуры: MVI, навигацию и базу данных.

* [/server](./server/src/main/kotlin) содержит каркас серверного приложения на Ktor.
  Прикладные маршруты пока не реализованы.

### Модули приложения

Код из `taskb_desktop` перенесён в следующую структуру модулей:

| Модуль | Назначение |
| --- | --- |
| `:core:mvi` | Общие контракты Store и инфраструктура MVI. |
| `:core:navigation` | Инфраструктура навигации и навигационный контейнер Compose. |
| `:core:database` | Настройка локальной базы данных и доступ к ней. |
| `:core:utils` | Универсальные утилиты проекта, включая получение текущей даты. |
| `:ui` | Тема TaskB, палитра, иконки и переиспользуемые компоненты интерфейса. |
| `:feature:calendar` / `:feature:calendar:api` | Месячный календарь для широкого экрана, перенос задач с отменой и публичные маршруты. |
| `:feature:hello` / `:feature:hello:api` | Реализация экрана приветствия и публичные контракты. |
| `:feature:home` / `:feature:home:api` | Реализация главного экрана и публичные контракты. |
| `:feature:settings` / `:feature:settings:api` | Экран Settings, сохранение настроек приложения и публичные контракты. |
| `:feature:weather` / `:feature:weather:api` | Прогноз Open-Meteo на 10 дней и публичные модели погоды. |
| `:feature:holiday` / `:feature:holiday:api` | Официальные праздничные даты Enrico, месячный кэш и публичные модели/DAO. |
| `:feature:group` / `:feature:group:api` | Группы и их редактор, модели, DAO и публичный контракт репозитория групп. |
| `:feature:item` / `:feature:item:api` | Задачи и события как типы `Item`, общий редактор, повторения, репозитории и маршруты. |

`:app:shared` объединяет модули приложения для платформенных точек входа.
Каталог `core` объединяет самостоятельные модули `:core:mvi`, `:core:navigation`,
`:core:database` и `:core:utils`; отдельной библиотеки `:core` нет.
Универсальные утилиты хранятся в `:core:utils` и доступны другим модулям через явную
зависимость. `currentDate()` находится в пакете `com.mkulikov.taskb.core.utils.time`.
Зависимости между модулями повторяют структуру настольного проекта: фичи обращаются к другим
фичам через их модули `api`, а `:core:database` зависит от API-модулей групп, элементов календаря, праздников и настроек.
Календарь и редактор элементов получают группы через `IGroupRepository` из `:feature:group:api`;
реализацию репозитория и навигацию групп регистрирует `groupModule` в `:app:shared`.

В общие модули перенесены MVI, навигация на Navigation 3, база данных на Room 3 и настройки
приложения. Подключены Coroutines, Koin, Compose Material и Material Symbols.
Экраны приветствия, главного меню, календаря, групп и редакторы находятся в `commonMain`
вместе со Store, состояниями, Intent, reducer и репозиториями. Desktop и Android используют
эти реализации через `:app:shared`. Интерфейс TaskB поддерживает светлую и тёмную темы,
компактную и широкую компоновки с отдельными экранами создания и редактирования.
Черновики и открытые селекторы сохраняются при изменении ширины окна и переходах
к другим экранам поверх редактора. Публичные `ItemCreationRoute(initialDate, initialGroupId, initialType)`,
`TaskEditorRoute(taskId, occurrenceId)`, `EventEditorRoute(eventId, occurrenceId)` из `:feature:item:api`,
а также `GroupEditorRoute.Create`
и `GroupEditorRoute.Edit(groupId)` из `:feature:group:api` можно открывать через
`IAppNavigator.navigate` из любой фичи. Маршрут списка `GroupsRoute` также находится
в `:feature:group:api`.
Выбор группы открывается отдельным экраном `GroupSelectionRoute(resultKey, selectedGroupId,
showNoGroup, noGroupSelected)` из `:feature:group:api`. Редактор элемента передаёт
`showNoGroup = false` и позволяет очистить группу отдельной кнопкой. Выбор возвращает `GroupSelectionResult(groupId)` через `IAppNavigator.backWithResult`;
`groupId = null` означает явный выбор «No group», обычный возврат не меняет выбор.
Получатель создаётся через `createResultReceiver` и хранится в `rememberNavEntryResource`:
результат ждёт возобновления вызывающего экрана и освобождается вместе с его записью навигации.
В широком селекторе доступна кнопка New group, в узком — иконка плюса. Они открывают
редактор новой группы поверх селектора; после сохранения группа появляется в списке,
а поисковый запрос, текущий выбор и черновик вызывающего редактора сохраняются.
Экран Settings открывается кнопкой с шестерёнкой в тулбаре календаря. В общем
разделе Location можно найти город, выбрать его или очистить локацию. Её используют
и погода, и праздники через `IAppLocationRepository` из `:feature:settings:api`.
Город, координаты, часовой пояс, код страны ISO alpha-2 и название региона сохраняются
в `application_settings` под ключом `appLocation`. Поиск города принадлежит Settings
и использует Open-Meteo Geocoding API. Пока локация не выбрана, запросы погоды и
праздников не выполняются.

Прежний `weatherLocation` переносится автоматически при чтении настроек; погода
продолжает работать. Если у старой записи нет кода страны, геокодер дополняет её
страной и регионом только при единственном совпадении сохранённых координат и
часового пояса. Название и координаты выбранного города сохраняются. Страна не
угадывается по тексту названия; при неоднозначном результате или ошибке сети можно
заново выбрать город в Settings. Очистка общей локации сохраняется и исключает
восстановление старого значения.

`:feature:weather` получает суточные коды погоды и минимум/максимум температуры в °C
из [Open-Meteo Forecast API](https://open-meteo.com/en/docs). Общая локация выбирается
через [Geocoding API](https://open-meteo.com/en/docs/geocoding-api). Запрашиваются сегодня
и следующие девять дней в часовом поясе выбранного города (`forecast_days=10`).
Календарь зависит только от `:feature:weather:api`; реализации объединяются в
`:app:shared` через Koin. Сетевой клиент закрывается вместе с `AppDependencyGraph`.
Сетевые реализации подключены для Desktop и Android; iOS/Web сохраняют общий API
и пока не выполняют погодные запросы.

Прогноз кэшируется в памяти на час; проверка обновления и повтор после ошибки идут
каждые 15 минут, в том числе при смене даты в городе. Переключение месяца не создаёт
новый запрос. При сбое обновления остаются доступные данные кэша;
прошедшие даты скрываются. Ошибка погоды не блокирует задачи.
В заголовке ячейки после номера дня с отступом 4dp отображаются значок и минимум/максимум;
при недостаточной ширине остаются значок и максимум. Данные не интерполируются
за пределами прогноза; пропуски температуры не заменяются нулями.

Для погоды используется согласованный живописный набор из десяти цветных PNG.
Оптимизированные ресурсы 96×96 с прозрачностью находятся в
`ui/src/commonMain/composeResources/drawable/weather_*.png` и доступны через `TaskBIcons`.
Календарь отображает их размером 20dp без цветового тонирования. У мороси, дождя
и сильного дождя отдельные значки. Исходники высокого разрешения и промпты хранятся
локально в `~/TaskB/weather-icons-painterly-v2`. Ресурс можно экспортировать через ImageMagick.

```bash
magick ~/TaskB/weather-icons-painterly-v2/sunny.png \
  -filter Lanczos -resize 96x96 -depth 8 -strip -define png:compression-level=9 \
  ui/src/commonMain/composeResources/drawable/weather_sunny.png
```

Данные Open-Meteo распространяются по [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)
с обязательной атрибуцией. Ссылки на Open-Meteo и лицензию находятся в блоке Data sources
экрана Settings. Там же доступна ссылка на сервис праздников Enrico. Бесплатный публичный
API предназначен для некоммерческого использования и не требует ключа; для коммерческого
распространения нужен соответствующий [план Open-Meteo](https://open-meteo.com/en/pricing).

`:feature:holiday` запрашивает публичные праздники через
[Enrico 2.0](https://kayaposoft.com/enrico/json/v2.0/docs.php):
`getHolidaysForMonth`, `holidayType=public_holiday`, страна, регион (если нужен), год
и месяц. Поддерживаются страны, регионы и диапазоны дат, заявленные сервисом, включая
Россию; это агрегатор праздничных дат, а не единый государственный источник всех
местных праздников мира. При неподдерживаемой локации или месяце праздники не
загружаются; задачи и события остаются доступны. Названия праздников берутся на
английском.

Загрузка выполняется при открытии месяца календаря или выборе даты другого месяца
для боковой панели. При запуске приложения нет предварительной годовой загрузки.
Перед сетью проверяется таблица `holiday_months`: если успешный снимок локации и месяца
уже есть, праздники читаются из `holidays` без HTTP, в том числе после перезапуска.
Успешный пустой ответ тоже отмечает месяц загруженным. Для нового месяца при первом
промахе дополнительно проверяется каталог покрытия Enrico; метаданные хранятся в
памяти клиента. Ошибка сети или ответа не сохраняется как успешная загрузка.
Смена локации переключает кэш страны/региона, а её очистка убирает праздники из интерфейса.

Схема Room версии 12 добавляет `holiday_months` и `holidays`; миграция 11→12 сохраняет
существующие задачи, события, группы и настройки. Снимок месяца и его праздники
записываются одной транзакцией. История схем находится в `core/database/schemas`.
Для Desktop и Android подключены HTTP-клиенты; iOS/Web сохраняют API и платформенные
каркасы. Клиенты освобождаются вместе с `AppDependencyGraph`.

Праздники отображаются первыми в блоке Events боковой панели и перед событиями в
ячейках. В прошедших днях активные просроченные задачи остаются выше праздников.
Строки праздников нельзя открыть, удалить, отметить выполненными или перетащить.
Полоска перед названием — `Palette.Green.s900`, 4.5dp (в 1.5 раза толще полоски события).
В месячной сетке название всегда занимает одну строку с многоточием при нехватке места.

Календарь — корневой экран приложения. При первом запуске и после обновления сначала
появляется приветствие. Кнопка Get started открывает календарь и подтверждает показ
для текущей версии. Если закрыть приложение до нажатия, приветствие появится снова.
При следующих запусках подтверждённой версии сразу открывается календарь.
Слева находится список, справа — месячная сетка.
При открытии выбран сегодняшний день. Нажатие на день, его число или «+N more»
показывает задачи и события этой даты. Снятие фильтра по дате открывает общий список задач.
Поиск и диалог Filters позволяют отобрать задачи по названию, признаку и группе.
Под названиями задач в панели отображаются описания.
Перетаскивание мышью или длительное нажатие с переносом меняет только дату задачи;
плашка Undo позволяет отменить последний перенос в течение трёх секунд.
Одинарные стрелки в тулбаре, колесо над сеткой и горизонтальные свайпы переключают месяцы.
Двойные стрелки переключают год, сохраняя месяц. На Desktop это также можно сделать
через Ctrl + колесо над сеткой. Название задачи или события открывает общий редактор.
Кнопка «+» открывает редактор создания с выбранной датой и группой. Тип элемента
выбирается в редакторе.
Today возвращает текущий месяц и задачи сегодняшнего дня.
Отдельная компоновка календаря для узких экранов пока не реализована.
После сохранения, удаления или возврата редактор закрывается к вызывающему экрану;
фильтры списков сохраняются. На широких экранах формы выровнены по центру,
действия находятся в экшенбаре, статистика группы — над полями формы.

У задач задаётся только дата; время начала и окончания доступны исключительно событиям.
В общем редакторе группа находится рядом с названием. Для события ниже расположены Date и End date.
Дата обязательна: новая форма открывается на выбранном дне календаря или сегодня,
End date по умолчанию совпадает с Date. Кнопок очистки дат нет. Для события без времени
диапазон включает обе даты, например отпуск с 5 по 20 ноября занимает все 16 дней.

В необязательном блоке Time выбирается время начала в 24-часовом формате. После выбора
появляется End time с окончанием через 30 минут. При переходе через полночь End date
увеличивается автоматически. Если многодневный диапазон уже выбран, он сохраняется.
Кнопки 15 min, 30 min и 1 hour расположены под Time и видны только при совпадении Date
и End date. Отдельного блока Duration нет; произвольное окончание задаётся через End date
и End time. Очистка Time убирает часы начала и окончания, сохраняя выбранный диапазон дат.
Время хранится как местное календарное время и не меняется при смене часового пояса устройства.

При обновлении базы до версии 9 существующие задачи со временем автоматически переносятся
в события. Если время задано в любом расписании или отдельном вхождении повторяющейся задачи,
переносится вся серия, включая её историю и вхождения без времени. Сохраняются название,
описание, группа, дата создания, даты, время, длительность, правила повторения, переносы,
пропуски и индивидуальные изменения времени. У событий нет статуса завершения; завершённые
задачи тоже переносятся без этого статуса. Перенесённые записи удаляются из задач,
существующие события и задачи без времени сохраняются. Перенос выполняется однократно
в транзакции обновления базы. Миграция до версии 10 дополнительно переносит задачи со временем,
которые могли быть созданы в версии 9, затем удаляет поля времени и длительности из таблиц задач,
их расписаний и вхождений. Миграция до версии 11 добавляет длительность событий без времени
в днях, сохраняя даты, время, длительности и исключения существующих событий.

События отображаются в календаре и боковой панели выбранного дня.
В ячейках календаря сначала идут события без времени, затем события с точным временем,
затем задачи. События с точным временем отсортированы по времени начала.
События со временем идут в сетке по времени,
без чекбоксов и подложки. Все события, в том числе на весь день, оформлены вертикальной
полоской цвета группы без иконки календаря; у событий без группы полоска скрыта.
Для многодневного события каждая занятая дата
получает отдельную запись: время начала перед названием в первый день и время окончания
после названия в последний. Окончание ровно в полночь не занимает следующий день.
У событий без времени все ячейки, включая первую и последнюю, содержат только название,
без подстановки 00:00 или 24:00. Это же правило действует для событий на один день.
В боковой панели все события собраны в разделе Events: сначала события на весь день,
затем события с точным временем по времени начала. Основные задачи находятся в разделе Tasks;
продолжительность указана в скобках после диапазона. Прошедшие события
показаны серым без зачёркивания. Перенос любого сегмента сдвигает всё событие по дням,
сохраняя время и длительность.

Переключатель Show in calendar в редакторе задачи управляет её отображением в ячейках
месячной сетки и участием в счётчике «+N more». Он включён по умолчанию для новых задач.
Просроченные задачи отображаются в ячейках независимо от положения переключателя.
Миграция Room 12→13 выключает его у существующих задач с повторением каждый день
(Daily, интервал 1).
В боковом списке выбранного дня незавершённые повторяющиеся задачи показаны в разделе Recurring
перед Events и Tasks независимо от положения переключателя.
Переключатель Quick delete доступен для повторяющихся задач и выключен по умолчанию.
В боковом списке календаря он добавляет кнопку удаления незавершённого экземпляра с подтверждением.
Завершённые задачи всех типов переходят в общий раздел Completed внизу бокового списка,
где последние завершённые идут первыми. При снятии отметки задача возвращается в свой
раздел. В общем списке задач, включая фильтр No date, выполненные задачи видны 24 часа.
Каждый раздел сворачивается нажатием на стрелку или текст заголовка; стрелка указывает
его состояние. Пустое место справа не реагирует на нажатия, подсветки при наведении нет.
При открытии календаря и выборе другого дня все разделы раскрыты.
Выполненные дела остаются в истории выбранного дня; пропущенные вхождения скрыты.

Повторяемость настраивается в редакторе после выбора даты: ежедневная, по дням недели,
по числу месяца или по дню и месяцу года, с интервалом и окончанием по дате либо количеству
событий. Первое нажатие на селектор выбирает ежемесячное повторение в указанное число.
31-е число и 29 февраля при необходимости заменяются последним днём месяца; последующие
события возвращаются к исходному числу.

Серия остаётся одной сущностью `Task` с необязательным `ItemRecurrence`. Название, группа
и видимость в календаре общие для всех её вхождений. Календарь вычисляет вхождения только
для видимого диапазона.
В списке показываются последнее невыполненное просроченное событие и ближайшее событие
начиная с сегодняшнего дня. В общем списке календаря выполненные повторения видны в разделе Completed
в течение 24 часов. При выборе даты доступна история выполненных задач за этот день.

Перенос предлагает изменить только выбранное событие либо начать оставшееся расписание
с новой даты. Удаление предлагает пропустить одно событие, удалить его и последующие
или удалить задачу вместе со всей историей. Отмена переноса доступна для одного события;
перенос всей последующей серии не предлагает Undo. Изменение правила создаёт новый период
расписания в `task_schedules`, сохраняя завершённую историю прежнего периода. Отдельные
переносы, пропуски и отметки выполнения хранятся в `task_occurrences` по ключу периода
и исходной запланированной даты. Новое расписание не переписывает завершённые события;
его начало должно следовать за выполненной историей. Дублировать запись самой задачи
при изменении расписания не требуется.

Перенесены создание, редактирование и удаление задач и групп, поиск, сортировка,
фильтрация, отметка выполнения, выбор группы и даты. Работа с датами использует
`kotlinx-datetime`; в базе по-прежнему хранится число дней от 1970-01-01, поэтому
существующие сроки задач остаются совместимыми. Новые тексты интерфейса — на английском.
На Desktop сохранён системный шрифт Noto Sans, на остальных платформах используется
системный sans-serif. Цвета и иконки задаются через `Palette`, `TaskBTheme` и `TaskBIcons`.

Исходники используют единый базовый пакет `com.mkulikov.taskb`. Имя класса базы данных
сохранено, чтобы использовать прежнюю историю схем Room.

Общие настройки сборки вынесены в Gradle convention plugins в [/build-logic](./build-logic):

* `taskb.multiplatform.library` настраивает целевые платформы Android, JVM, iOS ARM64,
  iOS Simulator ARM64, браузерные JS и Wasm, а также `kotlin-test` в `commonTest` и тесты
  Android, выполняемые на JVM. Байт-код библиотек для Android и JVM рассчитан на Java 11,
  как и в Android-приложении.
* `taskb.compose.library` дополнительно включает Compose, компилятор Compose, ресурсы Android
  и зависимости для Compose Preview: аннотацию в `commonMain` и tooling в `androidRuntimeClasspath`.

Версии плагинов и Android SDK берутся из `gradle/libs.versions.toml`.
Общий код каждого модуля следует размещать в `src/commonMain/kotlin`, а тесты — в
`src/commonTest/kotlin`. Каталоги с кодом для отдельных платформ добавляются по мере необходимости.
Для компиляции iOS и запуска тестов в симуляторе требуется macOS.

### База данных и внедрение зависимостей

Сущности и DAO находятся в `commonMain` API-модулей групп, элементов календаря, праздников и настроек. `:core:database`
содержит общую конфигурацию Room и схемы версий 1–7. Текущая версия базы — 7:
при обновлении с версий 2–6 последовательно применяются миграции до текущей версии.
Миграция 4 → 5 добавляет расписания и исключения повторений, а 5 → 6 — многострочное
описание задачи с пустым значением для существующих записей. Миграция 6 → 7 добавляет
время начала и длительность для задач, периодов повторения и отдельных событий;
существующие задачи остаются без времени. Задачи, группы и отметки
выполнения сохраняются. Для версии 1 сохранено
прежнее пересоздание базы. Более новые версии схемы не принимаются.
Задачи хранят время создания `createdAt` и nullable-время завершения `completedAt`
в миллисекундах от Unix epoch. Новая задача получает время создания при сохранении;
отметка выполнения для прошедшей запланированной даты записывает конец этого дня
(23:59:59.999) в местном часовом поясе. Для перенесённого вхождения используется
его текущая дата. Для сегодняшних, будущих задач и задач без даты записывается текущее
время; снятие отметки очищает его. Ограничение видимости завершённых задач в 24 часа
отсчитывается от записанного времени завершения, история календаря сохраняется.
Повторная отметка выполнения сохраняет уже записанное время. При редактировании
время создания и актуальное время завершения сохраняются. При миграции старым задачам
назначается время обновления базы: оно становится `createdAt` и, для завершённых задач,
`completedAt`, поскольку прежняя схема не содержала исторических дат.
Room KSP генерирует реализацию базы и её конструктор отдельно для каждой целевой платформы.

| Платформа | Хранение | Драйвер |
| --- | --- | --- |
| Android | `taskb.db` в каталоге баз данных приложения | BundledSQLiteDriver |
| Desktop | Прежний путь TaskB с учётом ОС: XDG data, LocalAppData или Application Support | BundledSQLiteDriver |
| iOS | Пока не реализовано | — |
| Web, JS и Wasm | Пока не реализовано | — |

`appModule` объединяет модули базы данных, настроек, навигации и всех перенесённых фич. Реализации `App()` для
Desktop и Android передают фабрику базы общему приложению. Koin создаёт базу при первом обращении
и закрывает её при закрытии контейнера. Жизненным циклом контейнера управляет Compose.

Для iOS и Web оставлен минимальный экран-заглушка TaskB без инициализации базы и DI-контейнера.
Общие исходники и объявления targets сохраняются, а платформенное хранение и запуск
инфраструктуры будут добавлены, когда начнётся разработка этих версий.

### Версия приложения

Версия рассчитывается автоматически по тем же правилам, что в прежнем Desktop-проекте.
Файл [version-major.txt](./version-major.txt) задаёт базовую версию из двух целых чисел,
например `1.38` или `2.0`.

Ко второй части базовой версии прибавляется число коммитов основной линии истории
(`--first-parent`) после коммита, задавшего эту базу. Например, `1.38` становится `1.39`
после следующего коммита. Повторная сборка, незакоммиченные изменения кода и изменения
только пробелов в базовом файле не сбрасывают счётчик. Merge-коммит считается один раз.
Чтобы начать новую серию, измените базу, например на `2.0`, и закоммитьте файл.
До первого коммита новой базы используется её значение без прибавления коммитов.

Посмотреть текущую версию:

```bash
./gradlew -q printVersion
```

Рассчитанная версия задаёт `project.version` всех модулей, отображается на главном экране
и используется как `versionName` Android и версия Desktop-пакетов. Для Windows сохраняется
прежнее преобразование: `1.38` → `1.0.38`, чтобы соответствовать формату MSI.
Общий `AppVersion.kt` генерируется при сборке; редактировать его вручную не нужно.

Android `versionCode` равен общему числу коммитов основной линии истории, начиная с первого.
Он растёт при новых коммитах и не сбрасывается при смене базовой версии.
Для расчёта версии нужен установленный Git и полная история репозитория; в CI используйте
`fetch-depth: 0`, для shallow clone выполните `git fetch --unshallow`.

Реализация находится в convention plugin `taskb.versioning` в `build-logic`.
Перенесённые тесты проверяют смену базы, merges, повторные сборки, detached HEAD и ошибки
неполной истории. Интеграционный тест проверяет обновление версии после коммита с включённым
configuration cache и наследование версии модулями:

```bash
./gradlew :build-logic:test
```

### Запуск приложений

Используйте конфигурации запуска на панели инструментов IDE или следующие команды:

- Android-приложение, сборка отладочного APK: `./gradlew :app:androidApp:assembleDebug`
- Настольное приложение:
    - С горячей перезагрузкой: `./gradlew :app:desktopApp:hotRun --auto`
    - Обычный запуск: `./gradlew :app:desktopApp:run`
- Сервер: `./gradlew :server:run`
- Веб-приложение:
    - Wasm (быстрее, для современных браузеров): `./gradlew :app:webApp:wasmJsBrowserDevelopmentRun`
    - JS (медленнее, поддерживает старые браузеры): `./gradlew :app:webApp:jsBrowserDevelopmentRun`
- iOS-приложение: откройте каталог [/app/iosApp](./app/iosApp) в Xcode и запустите приложение оттуда.

### Сборка Desktop для распространения

Настройки находятся в [app/desktopApp/build.gradle.kts](./app/desktopApp/build.gradle.kts).
Из прежнего Desktop-проекта перенесены имя пакета `TaskB`, иконки для Linux, Windows и macOS,
настройка JDK 21 и [compose-desktop.pro](./app/desktopApp/compose-desktop.pro) с правилами
для Room и SQLite. В релизной сборке ProGuard обфусцирует код.
Версия пакетов автоматически рассчитывается из `version-major.txt` и истории Git.

Сборка обфусцированного приложения со встроенной Java без установщика:

```bash
./gradlew :app:desktopApp:createReleaseDistributable
```

На Linux результат находится в `app/desktopApp/build/compose/binaries/main/app/TaskB`.
Запуск: `app/desktopApp/build/compose/binaries/main/app/TaskB/bin/TaskB`.
На других платформах релизное приложение находится в `app/desktopApp/build/compose/binaries/main-release/app`.
Для локальной разработки подходят `run` и `hotRun`. На Linux задача `createDistributable`
собирает приложение без обфускации в `app/desktopApp/build/compose/binaries/main-dev/app/TaskB`.

Обфусцированные установщики собираются на соответствующей ОС:

| Система | Команда | Каталог результата |
| --- | --- | --- |
| Linux, RPM | `./gradlew :app:desktopApp:packageReleaseRpm` | `app/desktopApp/build/compose/binaries/main-release/rpm` |
| Linux, DEB | `./gradlew :app:desktopApp:packageReleaseDeb` | `app/desktopApp/build/compose/binaries/main-release/deb` |
| Windows, MSI | `./gradlew :app:desktopApp:packageReleaseMsi` | `app/desktopApp/build/compose/binaries/main-release/msi` |
| macOS, DMG | `./gradlew :app:desktopApp:packageReleaseDmg` | `app/desktopApp/build/compose/binaries/main-release/dmg` |

Для RPM нужен `rpmbuild`, для DEB — `dpkg-deb`. Подробнее об инструментах упаковки — в
[документации Compose Multiplatform](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html).

Чтобы собрать обфусцированное приложение и добавить ярлык в меню приложений Linux:

```bash
./gradlew :app:desktopApp:installLinuxDesktopEntry
```

Задача записывает `applications/com.mkulikov.taskb.desktop` в `$XDG_DATA_HOME`, а если
переменная не задана — в `~/.local/share`. Ярлык указывает на приложение в каталоге `build`;
после очистки сборки выполните задачу повторно. Путь к приложению и идентификатор ярлыка
те же, поэтому уже закреплённый ярлык запускает новую сборку.

### Запуск тестов

Используйте кнопку запуска рядом с кодом теста в редакторе IDE или задачи Gradle:

- Общие тесты фич на JVM Android: `./gradlew :feature:group:testAndroidHostTest :feature:item:testAndroidHostTest`
- Интеграционный тест DI-контейнера и базы приложения: `./gradlew :app:shared:jvmTest`

Все JVM-тесты инфраструктуры и фич, а также тесты вычисления версии:

```bash
./gradlew jvmTest :build-logic:test
```

Тесты проверяют обработку и отмену MVI-эффектов, навигационный стек, освобождение ресурсов,
миграции базы, внешние ключи, транзакции и сохранение настроек между запусками DI-контейнера.
Тесты фич проверяют фильтрацию, редактирование задач и событий, правила повторения,
обработку ошибок и повторные запросы.
